## Fixes

- **Codex quota windows that ended before their advertised reset were deleted rather than recorded.** A sample survived a save only if it belonged to a window that had run to its advertised end, or to the window currently in progress. Codex moves its reported weekly reset ahead of schedule, and a window that ended early matched neither: it never reached completeness, and the moment the reset moved it stopped being the current one. It was dropped in the same save that admitted the new reading, leaving no interval in which anything could rescue it. The window is now closed at the length it actually ran, before that save, so it qualifies as a completed cycle instead of being cleared as a fragment, and it appears in Window history like any other. The retention rule itself is unchanged — a genuine fragment is still dropped. [#256](https://github.com/Nanako0129/TokenBar/pull/256)

  How often this bit depends entirely on how often the provider moves its reset, which is a server-side behaviour rather than anything local. Measured against one account's raw Codex sample log — 10,911 readings that predate any of this work and have no retention applied — the reported reset moved beyond the old five-minute tolerance on **11.6% of consecutive readings**. On the same machine over the same period, Claude accumulated 49 completed cycles while Codex accumulated one. That gap is the bug, not a difference in how the two were used.

  The old tolerance was the other half of it. Deciding "this is a different window" reused the quantum that exists to smooth the jitter a provider reports *inside* one window, capped at five minutes, so a rolling reset that drifts continuously read as a new window almost every poll. The threshold now scales with the window it is judging; on a weekly window it is thirty minutes, chosen against that sample log, where it catches every one of the fifteen real resets and misfires twice. Windows shorter than 28 hours keep exactly the tolerance they had.

- **History lost before this update does not come back.** The samples were deleted at the time rather than mis-recorded, so nothing remains to rebuild from. If your Codex window history is near empty today, it stays that way and refills from here.

- **Windows kept this way are shorter than a full cycle**, because they ended when Codex reset rather than when the quota ran out — across the fifteen resets measured, twelve ended between 5% and 64% used. They are excluded from the pace projection, the deficit marker and run-out forecast that Historical mode learns: fitting a window that ended at 34% teaches the projection that a completed cycle ends there, and every forecast after it reads low. That exclusion is deliberate and applies only to the projection; the windows are kept, shown, and counted everywhere else.
