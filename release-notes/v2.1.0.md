## Features

- **A card offers to attribute your usage to subscriptions.** [#437](https://github.com/Nanako0129/syrtis/pull/437)

  Until usage is attributed, a subscription's window history lists 0 tokens and $0.00 for every window, which reads like an idle window rather than a missing setting. When nothing is attributed yet, a card at the top of Overview and of the Quota view on every client tab lists the suggested assignments, each as the source, its provider and the subscription it would count toward, and applies them in one click. Settings → Usage attribution suggests the same assignments. "Set up manually…" opens that page, and "Not now" hides the card for good. The window history also says why its figures are 0 and links to the page, and the "Nothing is classified yet" hints in Stats now open it too.

- **Grok Build models are listed under one name.** [#417](https://github.com/Nanako0129/syrtis/pull/417)

  Grok Build reports usage as `grok-4.6-build` while its session names `grok-4.6`, so one model showed up as two rows. Models, Monthly, Daily and the Grok quota card's per-model breakdown now list `grok-4.6` and `grok-4.7` once each, in one color. Totals are unchanged.

- **The menu bar gauge turns grey when its reading is old.** [#418](https://github.com/Nanako0129/syrtis/pull/418)

  The gauge used to draw the last reading in its warning colors however old it was. It now turns grey once the reading it shows is more than 30 minutes old, and takes its color back with the next fresh reading.

## Fixes

- **Setting the clock back could erase quota history.** [#415](https://github.com/Nanako0129/syrtis/pull/415)

  When the history file held readings stamped later than the current time, loading it dropped each such series whole. A poll that recorded anything then saved the loss. On a copy of a real history file with the clock set back 10 minutes, the previous version dropped 3 of 18 series in memory, 10,163 readings down to 3,780. That the next recording poll would have saved the loss was derived from the code, not run on the copy. This version drops only the 4 readings stamped in the future and keeps every series. Repairs made while loading are also written back to the file once, instead of being redone in memory on every load.

- **The window history said "Quota history could not be read. It will be retried." for good.** [#433](https://github.com/Nanako0129/syrtis/pull/433) [#434](https://github.com/Nanako0129/syrtis/pull/434)

  Some sources record no quota history: Antigravity read through the `agy` CLI, which carries no account identity, and a Grok Bot token that names no account. Reading their history failed on every update, and the failure was reported as one that would be retried. Their window history now shows "No earlier windows recorded yet." The retry message stays for history that exists and could not be read.

- **Model prices stopped updating while you were idle.** [#413](https://github.com/Nanako0129/syrtis/pull/413) — fixes [#191](https://github.com/Nanako0129/syrtis/issues/191)

  The model report, and the "Prices updated …" time on the Models card, only refreshed when an agent wrote new usage. While the dashboard is open, the report is now fetched again once it is an hour old.

- **A signed-in `agy` that Syrtis could not find started a login shell on every refresh.** [#402](https://github.com/Nanako0129/syrtis/pull/402) — relates to [#353](https://github.com/Nanako0129/syrtis/issues/353)

  When Antigravity's other routes fail and `agy` is signed in but not on the app's `PATH`, Syrtis starts a login shell to look for it. If that search found nothing, it ran again on the next refresh. It now runs at most once every 15 minutes.

- **Claude credential errors said only "could not be loaded".** [#411](https://github.com/Nanako0129/syrtis/pull/411) — relates to [#225](https://github.com/Nanako0129/syrtis/issues/225) and [#226](https://github.com/Nanako0129/syrtis/issues/226)

  Each failure now names its cause in a fixed message, and no message includes credential content. A Keychain credential with a character outside printable ASCII came back from macOS as hex and was treated as unusable. It is now decoded and read.

- **A malformed Codex token could skip the refresh check.** [#397](https://github.com/Nanako0129/syrtis/pull/397) — fixes [#385](https://github.com/Nanako0129/syrtis/issues/385), thanks [@snowman12320](https://github.com/snowman12320)

  A token with a missing, extra or empty segment could supply an expiry that kept Codex from refreshing. Such a token's expiry is no longer trusted, and the refresh falls back to the time of the last refresh.

- **Quota history that failed to load was described as never recorded.** [#405](https://github.com/Nanako0129/syrtis/pull/405)

  Past windows and the heatmap now say "Quota history could not be read. It will be retried." when a window's history failed to load and nothing is left to show.

- **The separators in the light glass panel were harsh.** [#436](https://github.com/Nanako0129/syrtis/pull/436)

  On macOS 27 in light mode, the lines under the row of views (Overview, Quota, Models…) and above the footer are now lighter. Dark mode is unchanged.
